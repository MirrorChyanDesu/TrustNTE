# ⏱️ 抓帧间隔（毫秒）- 设置说明

这个数字 = 截图两张之间的最小间隔，**每秒截图张数 ≈ 1000 ÷ 间隔**。
全软件共用一条截图通道，改这里全局生效，支持运行中实时修改。

### 📊 各数值实际效果（1080p 参考值，因机器而异）

| 填入数值 | 实际帧率 | CPU 占用 | 说明 |
| :--- | :--- | :--- | :--- |
| **0 ~ 9** | 强制按 10 执行 | 🔴 极高 | ⚠️ 纯负收益 |
| **10** | 约 90~100 张/秒 | 🔴 50~100% | 游戏可能掉帧 |
| **15** | 约 66 张/秒 | 🟡 33~67% | 音游冲榜推荐 |
| **20** | 50 张/秒 | 🟡 25~50% | 轻微负载 |
| **25** | 40 张/秒 | 🟡 20~40% | |
| **30** | 约 33 张/秒 | 🟢 17~33% | 几乎无感 |
| **50（默认）** | 20 张/秒 | 🟢 10~20% | 推荐 |
| **100** | 10 张/秒 | 🟢 5~10% | |
| **500 以上** | 基本忽略不计 | 🟢 极低 | 省电模式 |

> ⚠️ **为什么填 0 或 1 会适得其反？**
>
> 1️⃣ **截图有物理下限**：截一张 1080p 图，系统调用本身就要 5~10 毫秒。间隔填得比这还小，会变成"能截多快截多快"，物理上限只有 100~200 张/秒。
>
> 2️⃣ **多截的图 90% 直接被扔掉**：上层任务只按自己的节奏取"最新一张"，截图快过消费的部分，截完就被新图顶掉。
>
> 3️⃣ **游戏反而掉帧**：截图线程是高优先级，会跟游戏抢 CPU 核心，每张 1080p 图约 8MB，200 张/秒 ≈ 每秒 1.6GB 内存写入。

### 🎯 推荐档位

- **挂机 / 钓鱼 / 日常任务**：50（默认）
- **预览想更丝滑**：30
- **音游冲榜（追求判定精度）**：15~25
- **音游刷体力 / 日常打歌**：50 或更高，满分之后没必要烧 CPU

💡 **推荐用法**：音游冲榜前临时调低 → 打完调回 50 挂机，下一帧立即生效。

### ❓ 常见问题 (QA)

**Q：填低于 10 不是应该每秒 1000 张吗？不是应该更快吗？**

两个原因到不了：一是系统把低于 10 的值强制按 10 处理；二是就算不强制，截图本身耗时 5~10ms，物理上限也只有 100~200 张/秒。已经是掉帧风险档——所以 0 的实际效果是"游戏掉帧 + CPU 拉满 + 预览毫无变化"，纯负收益。

**Q：为什么我把间隔调很低，预览却没变流畅？**

预览/识别的消费节奏由任务引擎决定，不随截图频率变化。截图多出来的部分只会被丢弃，不会让预览更快。
